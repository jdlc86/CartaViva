## 4. S50 — análisis del requisito de firmas: **propuesta, NO decisión**

En esta sesión el propietario pidió revisar si el sistema de **firmas digitales Ed25519** exigido para Sabora es necesario y comentó que cree que Fleetia no utilizaba un mecanismo equivalente.

**Normativa consultada:** [release gobernado V1](../architecture/SABORA_GOVERNED_RELEASE_V1.md), [arquitectura candidata del controlador S43](../architecture/SABORA_S43_RELEASE_CONTROLLER_CANDIDATE_2026-11-19.md), [método de validación S45/S46](../architecture/SABORA_VALIDATION_OBSERVABILITY_METHOD_V1.md) y [provisión S43](../runbooks/SABORA_S43_RELEASE_CONTROLLER_PROVISIONING_CANDIDATE_2026-11-19.md).

**Hecho normativo vigente:** la operación de deploy/rollback exige firma Ed25519 vinculada al SHA, host, operación y ventana; el host verifica también expedientes/ledger. S43 plantea seis autoridades para expedientes y **nueve claves distintas** (propietario, seis custodios, reserva y receptor), más instalación autenticada, incluyendo `installation.json`. El primer despliegue ficticio tiene excepciones **limitadas** de revisión interna y aplazamiento de backups/restore, **no una excepción de firmas**. Las firmas autentican declaraciones/autorizaciones; no prueban que los controles materiales ocurrieron. Nueve claves distintas tampoco prueban independencia de nueve personas.

**Valoración técnica discutida, aún no aprobada:** el conjunto parece sobredimensionado para la primera prueba de un restaurante único sin usuarios reales. Se propuso **evaluar una simplificación integral**, conservando al menos SHA y hashes exactos, CI real, identidad SSH exclusiva y comando restringido, límites efectivos de Docker/red/servicios, permisos, registro duradero, rechazo de replay y autorizaciones expresas. Una firma Ed25519 externa del propietario sí añade una frontera de seguridad concreta frente a compromiso de GitHub Actions/credenciales; eliminarla no es equivalente a mantener la misma protección. Se podría conservar una firma única para operaciones especialmente sensibles, sujetándola a una decisión explícita de modelo de amenazas.

**Comparación con Fleetia NO verificada:** la creencia del propietario no constituye auditoría del despliegue de Fleetia. No inspeccionar, operar ni modificar Fleetia para sostener esta comparación sin un alcance autorizado. La discusión **no autoriza** eliminar firmas, bajar controles, cambiar contratos, editar verificadores de autorización, habilitar `SABORA_RELEASE_AGENT_READY` ni desplegar.

**Decisión pendiente y requisito de corrección integral:** antes de cambiar el modelo, presentar el riesgo residual, el control sustituto concreto y una propuesta de modificación de **normativa + controlador + workflows + pruebas negativas/integradoras**, sin bypass transitorio. Solo con aprobación expresa de la decisión normativa y del cambio, revisar su integración. No hacer pequeñas excepciones invisibles ni dejar código que aparenta exigir autoridades inexistentes.
